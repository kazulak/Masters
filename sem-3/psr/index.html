3PostgreSQL Data Model

Single Azure Database for PostgreSQL Flexible Server with the pgvector extension. Services share one instance but own their tables via schema-level Postgres roles. The book_embeddings.embedding column uses vector(1536) for Azure OpenAI text-embedding-3-small.

Key index: CREATE INDEX ON book_embeddings USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);

  }

  recommendations {
    uuid id PK
    uuid user_id FK
    varchar type "similar | widen | mood"
    uuid_arr book_ids "top-10 ordered"
    jsonb explanations "LLM-generated text per book"
    timestamptz computed_at
  }

No LLM call on the hot path. Results are precomputed and stored. Target response time is p99 < 100 ms.

6Trade-offs & Evolution

T1 - Shared PostgreSQL instance

Now: one Flexible Server with schema-level role isolation.

Risk: one service can exhaust shared connections.

Path: PgBouncer, read replica for Recommendation, then separate instances per service.

T2 - Service Bus to Kafka

Now: publish/subscribe through a thin MessageBus abstraction.

Risk: Standard tier retention and Kafka compatibility limits.

Path: swap implementation to Event Hubs Kafka endpoint or aiokafka.

T3 - Streamlit to React/Next.js

Now: Streamlit container with no business logic.

Risk: limited custom UI and weak mobile experience.

Path: add Next.js frontend, activate JWT validation, cut over DNS.

Embedding dimension lock-in

Now: vector(1536) matches current embedding model.

Risk: a different model dimension requires re-embedding.

Mitigation: treat embeddings as invalidatable cache using model_version.
